# 业务口径与目标分析表

状态：v0.1 设计草案，待阶段1源数据审计后冻结。以下规则是本练习的业务约定，不是已核实的原零售商内部政策。当前没有实际运行后的业务数值。

## 业务问题和粒度

运营人员每天查看：各国家发生了多少销售和取消冲销？净交易金额是多少？有多少销售无法识别客户？结果是否完整且通过检查？

首张表：`mart.daily_country_sales`。一行 = 一个业务日期 × 一个国家，币种固定 GBP。Country 表示源记录中的客户所在国家，不推定为配送国家。

| 字段 | 定义 |
| --- | --- |
| business_date | 源发票日期的日历日 |
| country | 清理首尾空格后的来源国家；缺失单列为 UNKNOWN |
| sales_invoice_count | 纳入正向销售的不同发票数 |
| identified_buying_customers | 正向销售中非空客户编号的去重数 |
| sales_amount_gbp | 纳入范围的正向记录数量 × 单价之和 |
| cancellation_amount_gbp | 纳入范围的 C 前缀负数量记录，金额取正数 |
| net_activity_amount_gbp | sales_amount_gbp − cancellation_amount_gbp |
| unidentified_sales_amount_gbp | 正向销售中客户编号缺失的金额 |
| accepted_line_count | 本日期/国家纳入的原始行数 |
| excluded_line_count | 能归属本日期/国家的已分类排除行数 |
| quarantined_line_count | 能归属本日期/国家的异常行数 |
| run_id / data_as_of / rules_version | 追溯本次运行、模拟到达截止点和业务规则版本 |

客户数不能跨日期直接相加当成期间唯一客户数。所有聚合以纳入范围为前提；各组发票数能否相加，须先验证发票是否跨国家/日期。无法归属日期的异常只进入运行质量报告，不能为了汇总强行制造业务日期。

## 初始分类规则

1. 原始层保留所有行和来源位置。编号按文本处理，不把 C 前缀或前导零丢掉。
2. 必须先核验发票号、日期、数量、单价和商品编码的有效性。日期解析失败、必需编号缺失、数量非整数等进入隔离表，记录原因。
3. 非 C 前缀、数量 > 0、单价 > 0，是正向候选；C 前缀、数量 < 0、单价 > 0，是取消候选。
4. 符号与前缀冲突、非正价格、零数量等进入分类审计，不靠取绝对值把它们全部变成退款或销售。
5. 商品、运费、折扣、手工调整等范围在阶段1查看实际编码后建立显式映射。不能仅按“编码是否全数字”认定商品。未分类项有独立计数；冻结口径前不发布销售总额。排除的调整项单独对账。
6. 缺失客户编号的有效记录保留金额，但不计入已识别客户数。不把所有缺失编号当成一个真实客户。
7. 同一发票若日期、国家或客户信息冲突，先报告并隔离受影响发票，待明确规则后处理，避免拆单重复计数。
8. 源文件中的相同行保留并标注重复疑点。没有可靠订单行ID，不直接按“发票号 + 商品号”删除记录。同一来源行的重复投递由导入清单防重。
9. 金额使用定点 DECIMAL；阶段1先看单价精度，再确定列精度和统一舍入策略。禁止先四舍五入单价而无声改变总额。
10. 销售按销售发生日计入；取消按取消发生日计入。没有可靠原单引用，不把取消回填到猜测的原订单。
11. 只有取消没有销售的日期/国家也必须保留；净额允许为负。不把它自动判成数据错误。
12. 来源发票时间没有已验证时区；暂按原始日历日期处理，不转换为悉尼业务日期。悉尼时间仅用于调度。历史首尾日是否完整须在报告中说明。

## 计算结构

销售、取消和质量统计各自先聚合到 日期 × 国家，再按完整键集合连接。这样避免将多个销售明细和多个取消明细相连后重复放大金额，也保留只有取消或异常的分组。

基础客户摘要可从已到达记录生成；不得读取未来回放日期的记录来补齐今天的客户信息。首版金额按每条交易自己的国家汇总，不用客户最新国家覆盖历史。

## 手算例子（教学构造，非 UCI 结果）

同一天、同一国家：A客户一张销售单含 2 件 × £10，另一张销售单含 1 件 × £5；另有一张取消单为 −1 件 × £10。

预期：销售单数2，已识别购买客户数1，销售金额25，取消金额10，净交易金额15。若取消单在第二天才发生，则第一天净额25、第二天净额−10。

稍后的真实数据验收，须从源文件选择记录并保留来源位置，独立手算后再对比 SQL。

## 必须通过的验证

- 分组键唯一；金额恒等式成立。
- 原始行数 = 纳入行数 + 明确排除行数 + 隔离行数；重复投递另记为跳过批次，不混入原始行数。
- 有可解析金额的每类记录分别对账；不可解析值单独报告，不能填0冒充对账通过。
- 先聚合再连接，连接后金额不增加。
- 同一批次重跑，业务列及稳定排序后的业务结果校验值不变；运行时间等元数据可以变化。
- 晚到记录、更正的旧/新分区重算后，与同截止点全量重建一致。
- 检查失败时，正式表和成功检查点均不前移。

## 若要练习“已到账退款”

另建明确标记为 synthetic 的退款测试场景，包含 refund_id、original_order_id、status、settled_at 和 amount。它可用于练习一单多次退款、未结算退款排除、超额退款检查，但不能当作这份真实数据中存在的字段或业务事实。
